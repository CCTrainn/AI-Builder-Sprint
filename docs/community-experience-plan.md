# 공동 경험 기능 기획 — 말대꾸 지도

상태: 팀 검토용 초안 (`DRAFT FOR TEAM REVIEW`)

담당 역할: `ROLE-COMMUNITY-EXPERIENCE`

## 1. 한 문장 정의

> 말대꾸 지도는 한 사람의 해결 과정을 개인정보가 제거된 경험으로 바꾸고,
> 비슷한 문제를 겪는 다음 사람에게 실제로 도움이 된 질문과 대응 흐름을
> 보여주는 공동 권리 지식이다.

제품 전체의 메시지:

> 말대꾸가 모이면, 권리가 됩니다.

이 기능은 피해자끼리 자유롭게 대화하는 커뮤니티가 아니다. 게시판, 채팅방,
사업장 평가 서비스가 아니라 익명화된 경험의 공통 패턴과 해결 경로를 찾는
구조화된 지식 기능이다.

## 2. 왜 필요한가

대화 AI는 한 사용자가 지금 무슨 말을 해야 하는지 돕는다. 하지만 사용자는
다음과 같은 불안을 계속 느낄 수 있다.

- 나만 이런 일을 겪는 것인지 모른다.
- 고용주의 말이 실제로 자주 사용되는 회피 표현인지 모른다.
- 비슷한 상황의 사람은 다음에 무엇을 물었는지 모른다.
- 질문을 계속했을 때 실제로 어떤 결과가 있었는지 모른다.

말대꾸 지도는 개인의 대화를 다른 사람의 원본 사례와 직접 연결하지 않고,
여러 익명 경험에서 반복되는 패턴과 해결 행동을 보여줘 이 불안을 줄인다.

## 3. 제품 안에서의 위치

```text
자료 업로드
-> 기록 비교
-> 증거 지갑
-> 말대꾸 AI가 확인 문장 생성
-> 고용주 답변 분석과 후속 질문
-> 사용자가 진행 상태와 결과 기록
-> AI가 익명 경험 초안 생성
-> 사용자가 내용 확인 및 공유 동의
-> 개인정보 제거와 공개 기준 검사
-> 말대꾸 지도에 익명 경험 한 점으로 추가
-> 다음 사용자가 비슷한 경험과 해결 경로 확인
```

기본 앱 사용 경로를 방해하지 않는다. 사용자가 대화 분석을 마친 뒤에만
`이 경험을 익명으로 남겨 다른 사람을 도울까요?`라는 선택지를 보여준다.
공유하지 않아도 증거 지갑과 대화 AI는 정상적으로 사용할 수 있다.

## 4. 핵심 컨셉: 경험이 점에서 지식이 되는 과정

처음에는 익명 경험 하나가 작은 점으로 보인다. 경험이 쌓이면 같은 문제 유형,
고용주의 답변 패턴, 도움이 된 다음 질문이 선으로 연결된다. 충분한 수가 모이면
사용자는 다음 내용을 한눈에 볼 수 있다.

- 이 문제가 얼마나 반복해서 나타났는지
- 어떤 답변 패턴이 자주 등장했는지
- 사람들이 다음에 무엇을 확인했는지
- 어떤 기록이 문제 해결에 도움이 되었는지
- 해결 상태가 어떻게 달라졌는지

표현 방식은 실제 사람이나 사업장을 지도 위에 찍는 방식이 아니다. 문제 유형을
중심으로 점과 연결선을 사용하는 `경험 그래프`로 표현한다.

예시:

```text
시급 기록 차이 24건
├─ "수습기간이라 그래요" 11건
│  ├─ 수습 기간 질문 8건
│  └─ 계산 근거 요청 6건
├─ "다음 달에 줄게요" 7건
└─ 명확한 계산표를 받은 경험 9건
```

### 4.1 Obsidian 그래프 뷰 방식의 경험 탐색

말대꾸 지도의 대표 화면은 Obsidian 그래프 뷰처럼 점과 선으로 구성한다.
문서 파일 대신 다음 다섯 종류의 익명 노드를 연결한다.

```text
● 문제 유형       예: 계약 시급과 실제 시급의 차이
● 익명 경험       예: 음식점 근무자의 가공된 해결 과정
● 답변 패턴       예: "수습기간이라 그래요"
● 확인 행동       예: 수습 적용 기간 질문
● 도움이 된 기록  예: 근로계약서, 급여명세서
```

노드 사이의 선은 `어떤 문제에서`, `어떤 답변을 받고`, `무엇을 확인했으며`,
`어떤 기록이 도움이 되었는지`를 의미한다. 사용자가 기록 비교나 대화 분석에서
들어오면 자신의 현재 문제를 가운데 두고 가까운 경험부터 보여준다.

```text
                   [급여명세서]
                         |
[계산 근거 요청] -- [내 시급 차이] -- [수습기간 주장]
        |                |                  |
 [차액 확인 경험]   [익명 경험 묶음]   [기간 질문 경험]
```

그래프 표현 규칙:

- 가운데 주황색 노드: 사용자의 현재 문제
- 큰 남색 노드: 경험이 많이 모인 문제 유형
- 초록색 노드: 도움이 된 확인 행동과 기록
- 회색 노드: 반복해서 등장한 고용주 답변 패턴
- 점선 테두리: 아직 경험이 적거나 검증되지 않은 묶음
- 실선 테두리: 기록이 연결된 경험 묶음
- 노드 크기: 공개 가능한 경험 수의 구간
- 선 굵기: 두 패턴이 함께 나타난 빈도의 구간

재식별 위험이 있으면 정확한 건수를 보여주지 않고 `경험이 적음`,
`여러 경험에서 반복`, `자주 반복` 세 단계로만 표현한다.

### 4.2 그래프 상호작용

- 노드 선택: 연결된 경로만 강조하고 나머지는 흐리게 표시
- 노드 상세: 공통 답변, 확인 행동, 도움이 된 기록을 오른쪽 패널에 표시
- 내 상황 중심: 사용자의 현재 문제 노드로 즉시 복귀
- 필터: 문제 유형, 업종 대분류, 진행 상태, 도움이 된 기록
- 경로 보기: `문제 -> 답변 패턴 -> 확인 행동 -> 결과`만 남겨 표시
- 내 말대꾸에 참고: 선택한 행동을 내 기록 기반 후속 문장으로 다시 생성
- 목록으로 보기: 그래프 사용이 어려운 사용자를 위한 동일 정보 목록

그래프에는 사업장, 실명 사용자, 정확한 지역과 날짜를 노드로 만들지 않는다.
여러 필터를 조합해도 특정인을 추정할 수 없도록 최소 공개 묶음 기준을 적용한다.

## 5. 사용자에게 보이는 핵심 화면

### 화면 A. 내 경험 정리

대화가 끝난 뒤 AI가 다음 형식으로 초안을 만든다.

```text
문제 유형: 계약 시급과 실제 계산 시급의 차이
확인한 기록: 근로계약서, 급여명세서
고용주 답변 패턴: 수습기간 주장
내가 다음에 한 질문: 수습 적용 기간과 계산 근거 요청
현재 상태: 답변을 기다리는 중
```

사용자는 각 문장을 수정하거나 삭제할 수 있다. 원본 문서와 원본 대화는 공유
대상에 포함하지 않는다.

### 화면 B. 익명화 확인

공개 전에 앱이 제거하거나 일반화한 항목을 사용자에게 보여준다.

```text
부산광역시 해운대구 -> 부산 지역
2026년 7월 18일 -> 2026년 하반기
해운대 스시하우스 -> 음식점
시급 10,500원 -> 계약보다 낮은 시급
```

사용자가 최종 내용을 확인하고 명시적으로 동의해야만 게시할 수 있다.

### 화면 C. 말대꾸 지도

첫 화면에는 사람의 게시글 목록이 아니라 Obsidian과 비슷한 경험 그래프를
보여준다. 사용자의 현재 문제를 가운데 두고 비슷한 익명 경험, 반복된 답변,
도움이 된 질문과 기록을 선으로 연결한다.

```text
시급·급여 차이        24개의 익명 경험
근무시간 변경          17개의 익명 경험
수습기간 주장          11개의 익명 경험
급여 지급 지연          9개의 익명 경험
```

각 묶음은 점의 크기와 연결선으로 반복 정도를 표현한다. 표본이 적은 항목은
정확한 숫자를 숨기고 `아직 경험이 적어요`라고 표시한다.

선택한 노드의 상세 내용은 그래프 오른쪽 패널에 쉬운 문장으로 표시한다.

```text
수습기간 주장

여러 시급 차이 경험에서 반복된 답변이에요.
사람들은 다음에 수습 적용 기간과 계약서의 수습 조건을 확인했어요.

[연결된 경험 보기] [내 말대꾸에 참고]
```

### 화면 D. 비슷한 경험 상세

사용자가 문제 유형을 선택하면 개인 게시글 대신 공통 패턴을 먼저 보여준다.

```text
자주 등장한 답변
"수습기간이라 그래요"

사람들이 다음에 확인한 내용
1. 수습 기간의 시작일과 종료일
2. 계약서에 수습 조건이 있는지
3. 실제 시급 계산 근거

도움이 됐다고 기록된 자료
근로계약서, 급여명세서, 입금 기록
```

필요한 경우 개별 익명 경험을 열어볼 수 있지만, 사업장명·정확한 날짜·원문은
보여주지 않는다.

### 화면 E. 내 대화로 가져오기

비슷한 경험을 본 사용자는 `내 말대꾸에 참고하기`를 선택할 수 있다. 공동 경험의
문장을 그대로 복사하지 않고, 자신의 증거 지갑 기록과 현재 대화 맥락을 기준으로
AI가 새 확인 문장을 만든다.

## 6. 공유 단위

공유 가능한 정보:

- 표준화된 문제 유형
- 사용한 기록 종류
- 기록 사이에서 발견된 차이의 종류
- 고용주 답변의 익명 패턴
- 사용자가 다음에 확인한 항목
- 진행 상태와 해결 상태
- 도움이 된 기록 종류와 행동
- 업종 대분류, 넓은 지역, 넓은 시기

공유하지 않는 정보:

- 원본 문서 및 이미지
- 원본 대화 캡처와 전체 대화 원문
- 이름, 전화번호, 계좌번호, 외국인등록번호
- 사업장명, 지점명, 상세 주소
- 정확한 근무일, 대화일, 지급일
- 특정 개인이나 사업장을 추정할 수 있는 조합
- 사용자의 비자번호와 학교·학과 등 식별 정보

## 7. 개인정보 제거와 재식별 방지

1. 정규식과 문서 추출값으로 직접 식별자를 제거한다.
2. LLM은 구조화된 정보에서 간접 식별 가능 표현을 후보로 찾는다.
3. 지역은 시·도 또는 넓은 권역으로 일반화한다.
4. 날짜는 월·분기·반기 수준으로 일반화한다.
5. 금액은 정확한 액수보다 차이 유형 또는 구간으로 일반화한다.
6. 업종·지역·시기 조합의 경험 수가 5건 미만이면 공개 집계에서 숨긴다.
7. 사용자가 공개될 최종 결과를 직접 확인한다.
8. 동의 기록과 익명 사례는 분리 저장한다.

LLM이 `안전함`이라고 판단했다는 이유만으로 자동 게시하지 않는다.

## 8. 검증과 신뢰도

법적 사실 여부를 확정하지 않고 경험의 근거 수준만 표시한다.

```text
사용자 기록: 사용자가 직접 입력한 경험
기록 연결됨: 증거 지갑의 자료 종류와 연결된 경험
과정 확인됨: 질문과 답변 흐름이 앱에 저장된 경험
운영 검토됨: 개인정보와 공개 기준을 사람이 확인한 경험
```

화면에는 `법적 판정` 대신 다음 표현을 사용한다.

- 비슷한 기록 차이가 있었어요.
- 이런 답변 패턴이 반복됐어요.
- 다음 내용을 확인한 경험이 많았어요.
- 결과는 근무 조건과 상황에 따라 달라질 수 있어요.

## 9. 악용 방지

- 사업장명과 개인 식별 정보를 입력하면 게시를 중단한다.
- 욕설, 보복 요청, 신상 공개, 집단 공격 유도는 게시할 수 없다.
- 같은 사용자의 반복 게시에는 속도 제한을 둔다.
- 사용자는 자신의 경험을 비공개 또는 삭제 요청할 수 있다.
- 신고가 누적된 경험은 집계와 추천에서 즉시 숨긴다.
- 공개 사례는 고용주 평가나 블랙리스트 검색에 사용하지 않는다.
- 특정 사업장 단위의 검색 기능을 제공하지 않는다.

## 10. 첫 데이터가 없는 문제 해결

초기에는 실제 사용자 사례가 없으므로 다음 순서로 시작한다.

1. 팀이 완전히 가공한 데모 경험 12~20개를 만든다.
2. 임금 차이, 지급 지연, 근무시간 변경 등 3개 문제 유형만 사용한다.
3. 데모 경험에는 `시연용 가공 사례` 배지를 붙인다.
4. 실제 사용자 경험이 5개 이상 모인 묶음부터 실제 집계로 전환한다.
5. 데모 사례와 실제 익명 경험은 DB와 화면에서 구분한다.

공식 상담 사례나 보도 자료를 참고한다면 원문을 복사하지 않고 문제 유형과 해결
절차만 재구성하며 출처를 표시한다.

## 11. MVP 범위

1주 MVP에서 구현할 수 있는 최소 범위:

- 가공된 익명 경험 12개
- 가공 경험을 사용한 읽기 전용 그래프 뷰
- 문제·답변 패턴·확인 행동·기록의 네 종류 노드
- 노드 선택, 연결 강조, 오른쪽 상세 패널
- 그래프와 같은 정보를 제공하는 목록 보기
- 비슷한 답변 패턴과 다음 확인 항목
- 대화 완료 후 익명 경험 초안 미리보기
- 공유 전 개인정보 제거 결과 미리보기
- 실제 공개 대신 `공유 동의 완료`까지의 데모 흐름

MVP에서 제외:

- 사용자 간 댓글과 채팅
- 사업장 검색 및 평가
- 실제 자동 게시
- 실제 운영자 검수 도구
- 실제 신고 및 분쟁 연결
- 경험 기반 위법 확정
- 사용자가 직접 노드와 연결선을 편집하는 기능
- 대규모 그래프 탐색과 실시간 공동 편집

MVP 그래프는 새로운 프레임워크를 추가하지 않고 HTML, CSS, JavaScript와 SVG로
구현한다. 실제 데이터 공개 대신 완전히 가공된 데모 경험만 사용한다.

## 12. 성공 기준

- 사용자가 10초 안에 `나만 겪는 문제가 아니다`라는 의미를 이해한다.
- 비슷한 경험에서 다음에 확인할 항목을 한 개 이상 찾을 수 있다.
- 공동 경험에서 가져온 정보가 자신의 기록 기반 문장으로 다시 생성된다.
- 원본 개인정보가 화면과 API 응답에 존재하지 않는다.
- `개인 기록 -> 대화 -> 익명 경험 -> 다음 사람의 대화` 흐름이 데모에서 이어진다.

## 13. 팀 결정이 필요한 항목

- [ ] 기능 이름을 `말대꾸 지도`로 확정
- [ ] Obsidian 방식 경험 그래프를 대표 화면으로 확정
- [ ] 노드 종류와 연결 관계 확정
- [ ] 공유할 문제 유형 3개 확정
- [ ] 경험 공개 최소 묶음 크기를 5개로 확정
- [ ] 데모에서는 실제 게시 없이 공유 미리보기까지만 구현할지 확정
- [ ] 검증 상태 네 단계 확정
- [ ] 삭제 요청과 신고 처리 원칙 확정
- [ ] 팀이 문서 상태를 `APPROVED`로 변경

위 항목이 승인되기 전 허용되는 작업은 이 문서 수정과 완전히 가공된 익명 데모
경험 작성뿐이다.
