# 4인 개발 계획

## 제품 한 문장

외국인 노동자가 평소 근로자료를 모아두면, 기록 사이에서 달라진 조건을 찾아주고
고용주에게 확인할 말과 근거를 제공하는 근로자료 관리 서비스.

## 기술 구조

```text
HTML/CSS/JavaScript
        |
        | HTTP JSON
        v
FastAPI
  |-- 기록 업로드/OCR/조건 추출
  |-- 기록 비교
  |-- 법제처 법령 API
  |-- 확인 문장/답변 분석
        |
        +-- Supabase PostgreSQL: 구조화된 정보
        +-- Supabase Storage: 원본 PDF와 이미지
```

## 역할

| 역할 | 결과물 |
|---|---|
| 백엔드 정보 적재 | 업로드, Storage, OCR, 조건 추출, 비교, 법령 API |
| 백엔드 확인 대화 | 확인 문장, 번역, 고용주 답변 분석, 후속 질문 |
| 프론트 기록·비교 | 홈, 업로드, 타임라인, 비교 결과 |
| 프론트 대화·기록함 | 대화, 답변 분석, 근로 기록함 |

## MVP에서 비교할 조건

- 시간급
- 근로시간
- 급여일
- 수습기간
- 주휴수당

## 골든 데모

```text
채용공고: 시급 12,000원
-> 계약서: 시급 12,000원, 수습 조건 불명확
-> 급여명세서: 시급 10,500원
-> 앱: 기록이 1,500원 다르다고 표시
-> 법제처 API: 관련 조문 조회
-> 앱: 고용주에게 확인할 한국어 문장 제공
-> 고용주 답변: "수습기간이라 원래 그렇게 계산해요"
-> 앱: 기간, 합의 위치, 계산 근거가 답변되지 않았다고 표시
-> 후속 질문과 모든 기록을 근로 기록함에 저장
```

## 7일 일정

### 1일차

- 역할과 브랜치 확정
- API 계약과 DB 구조 확인
- Supabase 프로젝트와 private bucket 생성
- 프론트는 예시 JSON으로 시작

### 2~3일차

- 정보 적재: 업로드, Storage, OCR, 조건 추출
- 확인 대화: 문장 생성, 답변 분석
- 프론트: 각자 담당 화면 구현

### 4일차

- 기록 비교 규칙과 법령 API 연결
- 프론트에서 예시 JSON 전체 흐름 완성

### 5일차

- 실제 API 연결
- 로딩, 실패, 빈 화면 처리

### 6일차

- PDF 두 개와 고용주 답변으로 전체 시연 반복
- 다국어 화면과 개인정보 노출 확인

### 7일차

- 기능 추가 금지
- 배포, 오류 수정, 발표 연습

## 브랜치 흐름

```text
대회 원본: ApptiveDev/AI-Builder-Sprint
-> 팀 Fork: CCTrainn/AI-Builder-Sprint
-> develop에서 역할별 feature 브랜치 생성
-> feature Pull Request를 develop에 병합
-> 네 기능을 연결해 통합 테스트
-> 최종 develop Pull Request를 main에 병합
-> main을 심사·제출 버전으로 사용
```

팀원은 `main`이나 `develop`에 직접 푸시하지 않는다. 각자 자신의
`feature/역할-이름` 브랜치에서만 개발한다.

## 추후 별도 기획

공동 경험·증거 커뮤니티 기능은 이번 MVP 개발 범위에서 제외한다.
네 사람이 각자 맡은 핵심 기능을 완성한 뒤에도 바로 구현하지 않는다.

다음 내용을 팀이 먼저 결정한 후 별도 기능으로 계획한다.

- 어떤 목적의 공동 기능인지
- 다른 사용자에게 어떤 정보만 보여줄지
- 개인정보와 사업장 식별정보를 어떻게 제거할지
- 허위 정보와 악용을 어떻게 줄일지
- 비슷한 경험을 어떤 기준으로 연결할지
- 사용자가 공유를 명확하게 선택하도록 어떻게 동의를 받을지

기획이 확정되기 전에는 관련 화면, API, DB 테이블을 만들지 않는다.
