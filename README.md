## 왜 ‘말대꾸’인가요?

일터에서 조건이 달라졌거나 임금이 맞지 않아도 노동자는 관계가 틀어질까 봐 질문을 망설이기 쉽습니다. 특히 한국어가 익숙하지 않은 외국인 노동자에게는 무엇을, 어떤 근거로, 어느 정도 강하게 말해야 하는지 판단하는 일 자체가 큰 부담입니다.

말대꾸는 무례하게 맞서는 서비스를 뜻하지 않습니다. 기록을 바탕으로 차분하게 질문하고, 회피나 거절에도 대화를 포기하지 않으며, 자신의 권리를 지키는 데 필요한 말을 되찾는다는 의미입니다.

```text
흩어진 기록을 모으고
→ 달라진 조건을 발견하고
→ 근거 있는 한 문장을 만들고
→ 상대의 답변에 다시 대꾸하고
→ 해결 과정을 다음 사람의 경험으로 남깁니다.
```

AI는 위법 여부를 확정하거나 고용주를 자동으로 신고하지 않습니다. `기록이 다름`, `확인 필요`, `답변되지 않음`을 구분하여 사용자가 자신의 기록을 근거로 사실을 확인하도록 돕습니다.

## 핵심 기능

### 1. 자료 모으기 — 흩어진 근로 기록을 한곳에

채용공고, 근로계약서, 근무기록, 급여명세서, 입금내역, 고용주 메시지를 PDF 또는 이미지로 올릴 수 있습니다.

- PDF, JPG, JPEG, PNG 업로드
- Upstage Document Parse를 이용한 OCR
- 자료 유형에 맞춘 시급, 근무시간, 급여일, 휴게시간 등 조건 추출
- 원본 파일과 추출 결과를 연결해 보관
- 업로드 날짜가 아닌 자료가 실제로 적용된 기준일 관리

자료를 한 번 올리는 데서 끝나지 않고, 뒤의 기록 비교와 대꾸 AI가 같은 자료를 근거로 사용합니다.

### 2. 기록 비교하기 — 기억이 아니라 기록으로 확인

서로 다른 시점과 출처의 조건을 비교하여 달라진 항목을 보여줍니다.

- 채용공고와 근로계약서의 조건 비교
- 계약서와 실제 근무기록의 근무시간 비교
- 근무기록과 급여명세서의 인정 시간 비교
- 계약서·급여명세서·입금내역의 시급, 급여일, 지급액 비교
- 주휴수당 등 확인에 필요한 자료가 부족한 경우 추가 자료 안내

차이가 발견되더라도 곧바로 `불법`이나 `거짓말`이라고 단정하지 않습니다. 어느 기록의 어떤 값이 다른지, 확인하려면 무엇이 더 필요한지를 먼저 제시합니다.

### 3. 공식 기준 확인 — 주장에 근거 더하기

법제처 국가법령정보 공동활용 Open API를 통해 관련 공식 법령과 조문을 확인합니다.

- 비교 결과와 관련된 법령 제목 및 조문 안내
- 법률 용어를 쉬운 표현으로 설명
- 최신 원문을 확인할 수 있는 국가법령정보센터 링크 제공
- 공식 API를 사용할 수 없을 때에도 확인 경로 안내

법률 판단을 대신하는 것이 아니라, 사용자가 고용주에게 무엇을 확인해야 하는지 이해하도록 돕는 기능입니다.

### 4. 대꾸 AI — 대화가 해결될 때까지 다음 말을 제안

대꾸 AI는 단발성 문장 생성기가 아니라 실제 대화의 맥락을 이어 읽는 대화 도우미입니다.

1. 사용자가 확인하려는 문제를 선택합니다.
2. 기록 비교 결과와 공식 기준을 바탕으로 첫 질문을 제안합니다.
3. 사용자는 문장을 직접 수정한 뒤 실제로 보낸 내용을 대화에 남깁니다.
4. 고용주의 답변을 붙여 넣으면 AI가 답변 여부와 핵심 내용을 분석합니다.
5. 회피, 부분 답변, 거절, 반복 주장, 위협성 표현 등 상황에 맞는 다음 문장을 생성합니다.
6. 날짜, 금액, 지급 방식처럼 해결에 필요한 약속이 구체화될 때까지 후속 대화를 이어갑니다.

대화 중에는 불필요한 인사나 상대방의 말을 그대로 반복하지 않고, 앞선 대화와 현재 해결 목표에 맞는 자연스러운 답변을 생성합니다. 사용자는 추천 문장을 그대로 고르거나 수정할 수 있으며, 대화 기록을 수정·삭제·전체 초기화할 수 있습니다. 저장된 대화는 다른 페이지에 다녀와도 유지되고, 수정된 내용도 AI가 다시 읽습니다.

### 5. 다국어 대화 지원 — 이해하고 선택한 언어로 대꾸하기

한국어, 영어, 중국어, 베트남어, 인도네시아어를 지원합니다.

- 주요 화면과 안내 문구 번역
- AI 추천 문장을 선택한 언어로 제공
- 고용주의 한국어 답변을 사용자 언어로 해석
- 번역문과 실제 전송할 한국어 문장을 함께 확인

번역 때문에 대화의 맥락이 초기화되지 않으며, 언어를 바꿔도 같은 사건의 대화를 계속 이어갈 수 있습니다.

### 6. 근로 기록함 — 말로 끝내지 않고 과정으로 보관

실제로 주고받은 문장, 고용주의 답변, AI 분석, 아직 답변되지 않은 항목과 후속 조치를 한곳에 저장합니다.

- 사건별 전체 대화 흐름 보관
- 약속한 날짜, 금액, 처리 방식 기록
- 실제 입금이나 조건 변경이 이행되었는지 후속 확인
- 해결·미해결 상태와 다음 행동 정리

고용주가 “다음 주에 주겠다”고 답하는 것만으로 사건을 종료하지 않습니다. 약속한 날짜에 실제 지급 기록이 확인되는 등 사용자가 정한 해결 목표가 충족되었는지까지 추적합니다.

### 7. 공동 경험 — 한 사람의 대꾸를 다음 사람의 단서로

사건이 마무리되면 서비스가 대화와 처리 과정을 바탕으로 경험 초안을 자동 작성합니다. 사용자는 내용을 확인하고 수정한 뒤 하나의 경험으로 공유할 수 있으며, 공유 후에도 계속 수정할 수 있습니다.

- 유사한 문제를 겪은 사용자의 대응 과정 탐색
- 어떤 자료를 준비했고 어떤 질문이 효과적이었는지 확인
- 개인을 식별할 수 있는 이름, 연락처, 계좌번호 등 제거
- 원본 문서와 전체 대화는 공개하지 않고 요약된 경험만 공유
- 선택한 언어로 공동 경험과 사이드바 확인

공동 경험은 고용주 평가나 폭로 게시판이 아닙니다. 해결 과정에서 도움이 된 자료와 행동을 익명으로 나누어, 다른 사용자가 첫 질문을 시작할 수 있도록 돕는 공간입니다.

## 서비스 이용 흐름

```text
1. 근로자료 업로드
2. OCR 및 조건 추출
3. 계약·약속·실제 기록 비교
4. 달라진 조건과 필요한 추가 자료 확인
5. 관련 공식 법령 조회
6. 대꾸 AI로 첫 확인 문장 작성
7. 고용주 답변 입력 및 후속 대화
8. 약속 이행 여부를 새 기록으로 확인
9. 해결 과정과 결과를 근로 기록함에 보관
10. 익명화된 공동 경험 확정 및 공유
```

## 기술 구성

| 구분 | 구성 |
| --- | --- |
| 프론트엔드 | HTML, CSS, Vanilla JavaScript |
| 백엔드 | Python 3.11+, FastAPI, Uvicorn |
| 데이터베이스 | SQLite (`backend/local_data/work-rights.db`) |
| 원본 파일 | 백엔드 전용 로컬 저장소 (`backend/local_data/uploads/`) |
| OCR | Upstage Document Parse |
| LLM | Upstage Solar Pro 3 (`solar-pro3`) |
| 공식 법령 | 법제처 국가법령정보 공동활용 Open API |
| 테스트 | pytest |

FastAPI가 `/api/v1` API와 `frontend/` 정적 파일을 같은 출처에서 함께 제공합니다. 별도의 Node.js 빌드 과정은 없습니다.

## 로컬 기동 실행 가이드

### 1. 저장소 받기

```bash
git clone https://github.com/CCTrainn/AI-Builder-Sprint.git
cd AI-Builder-Sprint
```

### 2. Python 가상환경 및 의존성 설치

Python 3.11 이상이 필요합니다.

Windows PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
```

macOS/Linux:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

### 3. 환경변수 설정

`backend/.env.example`을 복사하여 `backend/.env`를 만듭니다.

```powershell
Copy-Item .env.example .env
```

```bash
cp .env.example .env
```

`.env`에 필요한 API 키를 입력합니다. `.env`는 절대 Git에 커밋하지 마세요.

### 4. 서버 실행

`backend` 디렉터리에서 실행합니다.

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

- 홈: http://127.0.0.1:8000/features/home/home.html
- 상태 확인: http://127.0.0.1:8000/api/v1/health
- API 문서: http://127.0.0.1:8000/docs

첫 실행 시 아래 경로가 자동 생성됩니다.

```text
backend/local_data/work-rights.db
backend/local_data/uploads/
```

### 5. 테스트 실행

```bash
cd backend
python -m pytest -q
```

## 환경변수 정보

환경변수는 `backend/.env`에서 관리합니다.

| 변수 | 필수 여부 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `APP_NAME` | 선택 | `Work Rights Companion API` | FastAPI 애플리케이션 이름 |
| `APP_ENV` | 선택 | `local` | 실행 환경 표시값 |
| `UPSTAGE_API_KEY` | 실사용 필수 | 없음 | Document Parse OCR 호출에 사용하며, 별도 LLM 키가 없으면 Solar 호출에도 사용 |
| `LLM_API_KEY` | 선택 | 없음 | Solar LLM 전용 키. 비어 있으면 `UPSTAGE_API_KEY` 사용 |
| `LAW_API_OC` | 선택 | 없음 | 법제처 공동활용 API의 OC 값 |
| `MAX_UPLOAD_BYTES` | 선택 | `10485760` | 업로드 파일 최대 크기. 기본 10MB |
| `LOCAL_DATA_DIR` | 선택 | `local_data` | SQLite DB와 업로드 폴더의 상위 경로 |
| `LOCAL_DB_NAME` | 선택 | `work-rights.db` | SQLite 파일명 |
| `LOCAL_UPLOAD_DIR_NAME` | 선택 | `uploads` | 원본 파일 저장 폴더명 |

예시:

```dotenv
APP_NAME=말대꾸 API
APP_ENV=local
UPSTAGE_API_KEY=your_upstage_api_key
LLM_API_KEY=
LAW_API_OC=your_law_api_oc
MAX_UPLOAD_BYTES=10485760
LOCAL_DATA_DIR=local_data
LOCAL_DB_NAME=work-rights.db
LOCAL_UPLOAD_DIR_NAME=uploads
```

API 키가 없을 때의 동작:

- `UPSTAGE_API_KEY`가 없으면 새 PDF·이미지의 OCR 처리를 완료할 수 없습니다.
- `LLM_API_KEY`와 `UPSTAGE_API_KEY`가 모두 없으면 대꾸 AI 생성·답변 분석·번역을 사용할 수 없습니다.
- `LAW_API_OC`가 없거나 법령 API 호출에 실패하면 관련 법령 제목과 국가법령정보센터 링크를 제공합니다.

## 실행 및 배포 환경 정보

### 현재 실행 구조

- 단일 FastAPI 프로세스가 API와 프론트 정적 파일을 함께 제공합니다.
- 데이터와 업로드 파일은 서버의 로컬 디스크에 저장됩니다.
- Docker, Vercel, Render 등 특정 플랫폼 전용 설정은 포함하지 않습니다.
- 로컬 MVP는 외부 PostgreSQL이나 Supabase 없이 실행할 수 있습니다.

### 배포 명령 예시

배포 서비스의 작업 디렉터리를 `backend`로 설정한 뒤 실행합니다.

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

배포 환경에는 환경변수를 비밀 값으로 등록하고 `.env` 파일을 업로드하지 마세요.

### 배포 시 주의사항

- `backend/local_data`를 영속 디스크에 연결해야 재배포나 재시작 후에도 DB와 파일이 유지됩니다.
- 영속 디스크가 없는 서버리스 환경에서는 저장한 기록과 대화가 사라질 수 있습니다.
- SQLite 구성은 단일 인스턴스 데모에 적합합니다. 여러 서버 인스턴스를 동시에 운영하려면 공유 PostgreSQL과 private object storage로 이전해야 합니다.
- 원본 근로자료에는 개인정보가 포함될 수 있으므로 업로드 폴더를 정적 공개 경로로 노출하지 마세요.
- 실제 운영 전 HTTPS, 접근 제어, 백업, 보존 기간과 삭제 정책을 별도로 마련해야 합니다.

## 빈 사이트에서 데모 데이터 적재하기

처음 실행하면 근로자료가 없는 빈 화면이 정상입니다. 저장소의 `output/pdf/`와 `demo-scenarios/`에 실제 개인정보를 사용하지 않은 시연용 문서가 포함되어 있습니다. 자료 모으기 화면에서 직접 업로드하면 전체 흐름을 시연할 수 있습니다.

| 순서 | 자료 유형 | 권장 날짜 | 확인할 수 있는 내용 |
| --- | --- | --- | --- |
| 1 | 근로계약서 | `2026-07-01` | 계약 시급, 근무시간, 휴게시간 |
| 2 | 급여명세서 | `2026-07-31` | 적용 시급, 인정 시간, 지급액 |
| 3 | 채용공고 | `2026-06-20` | 채용 당시 제시 조건 |
| 4 | 출퇴근 기록 | `2026-07-31` | 실제 근무시간 비교 |
| 5 | 입금내역 | `2026-08-10` | 명세 금액과 실제 입금 기록 비교 |

가장 간단한 데모는 근로계약서와 급여명세서 두 개만 업로드하면 됩니다.

```text
계약서의 시급 12,000원
→ 급여명세서의 적용 시급 10,500원
→ ‘기록이 다름’ 발견
→ 대꾸 AI로 적용 기준과 처리 계획 확인
→ 고용주 답변과 실제 입금 결과 저장
→ 익명 공동 경험 확정 및 공유
```

지원 파일은 PDF, JPG, JPEG, PNG이며 기본 최대 크기는 10MB입니다. 배포된 사이트가 저장소 파일을 자동으로 불러오지는 않으므로 자료 모으기 화면에서 데모 문서를 직접 선택해 업로드해야 합니다.

## 프로젝트 구조

```text
backend/        FastAPI API, 서비스, SQLite 저장 계층, 테스트
frontend/       HTML, CSS, JavaScript 화면
demo-scenarios/ 추가 데모 문서와 시나리오
docs/           API 계약, 데이터 구조, 협업 문서
output/         시연용 PDF와 데모 자료
scripts/        데모 자료 생성 보조 스크립트
```

## 개인정보와 서비스 범위

- 원본 파일과 전체 대화는 공동 경험에 자동 공개되지 않습니다.
- 공동 경험은 사용자가 초안을 확인하고 명시적으로 확정·공유한 경우에만 게시됩니다.
- 이름, 전화번호, 계좌번호, 외국인등록번호처럼 개인을 식별할 수 있는 표현은 공유 전에 제거해야 합니다.
- 말대꾸는 기록 정리와 확인 대화를 돕는 도구이며 법률 자문, 위법 여부 확정, 자동 신고 서비스가 아닙니다.
